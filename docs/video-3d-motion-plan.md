# Framecho 视频 3D 运镜开发方案

状态：设计草案，待评审；本阶段不修改应用代码。

## 1. 目标与首版边界

将录屏画面作为可做透视变换的平面卡片，在编辑过程中支持固定倾斜，以及随时间发生的倾斜、旋转、移动和推近。

首版实现：

- 整段视频的固定姿态：左右倾斜、上下倾斜、平面旋转、缩放和位置。
- 时间线中的运镜片段：基础姿态 → 目标姿态 → 保持 → 回到基础姿态。
- 左倾、右倾、俯视、轻微旋转、推近等预设，并允许修改目标姿态。
- 实时预览、保存重开、撤销重做、完整导出和云端分享。
- 与现有自动缩放、鼠标、点击效果、按键字幕、裁剪和变速协同。

这是对二维视频平面的三维投影，不会生成视频内容的深度信息。完整三维场景、设备模型、画面内部视差、自由相机路径和任意关键帧编辑留到后续阶段。

## 3. 用户操作设计

### 固定姿态

在视频编辑器检查器中增加「3D 运镜」分组：

- 总开关，关闭时显示原有平面视频。
- 左右倾斜、上下倾斜、平面旋转三个滑块，配合数值输入。
- 外层缩放与水平 / 垂直位置；与现有内容自动缩放分开命名。
- 「重置姿态」和「适配画布」操作。

首版以数值和滑块为主要交互。画布直接拖动旋转容易与裁剪、焦点选择冲突，后续再增加明确的「调整姿态」模式。

### 动态片段

时间线增加一条独立的「运镜」轨道，复用现有时间线缩放、选中、拖动及边缘调整方式。

1. 在播放头处点「添加运镜」，选择预设。
2. 检查器调整目标姿态、总时长、进入时间和退出时间。
3. 中间剩余时间为保持时间，清晰显示。
4. 拖动片段修改开始时间，拖动两端修改覆盖时长。
5. 支持启用 / 禁用、复制、删除、撤销和重做。

示例：从 3 秒开始，0.8 秒倾斜到右侧，保持 1.4 秒，再用 0.8 秒回正，总时长 3 秒。

首版同一轨道不允许片段重叠。添加时选择可用时间范围，拖动和调整时约束到相邻片段边界，避免出现隐含优先级。相邻片段的交界处都回到基础姿态。

因此首版无法表达「左倾直接转到右倾」这类连续运镜。这很可能是用户最先提出的需求，数据模型预留 `chainsFromPrevious` 字段（见第 4 节），首版固定为 `false` 且不在界面暴露；后续开启后，片段从上一片段的目标姿态出发，而不是先回到基础姿态。

切换预设只更新当前选中的运镜参数；项目载入和撤销操作不会更新用户的默认预设。

### 辅助编辑模式

- 编辑视频裁剪或缩放焦点时，临时以正面姿态显示卡片，并提示正在调整源画面；退出后恢复运镜。
- 摄像头和字幕保持现有画布位置，可继续正常编辑。
- 键盘操作、VoiceOver 标签、焦点顺序和禁用状态遵循现有编辑器模式。
- 「减弱动态效果」只影响界面提示和装饰动画，不改变用户视频的时间线、预览姿态或导出结果。

## 4. 合成层次与参数

合成顺序：

```text
原始视频
  → 源画面裁剪 / 现有自动缩放与平移
  → 合成鼠标、点击效果和按键字幕
  → 卡片圆角与透明边缘
  → 计算 3D 姿态并投影整个卡片
  → 在画布空间生成阴影，与背景合成
  → 合成摄像头小窗与转写字幕
  → 编码输出
```

鼠标和点击效果属于视频卡片；按键字幕保持卡片内的布局，但跟随卡片倾斜。转写字幕、背景与摄像头属于画布空间，默认保持固定。

所有卡片内元素先使用相同的局部坐标完成合成，再共同投影，避免视频倾斜而鼠标悬浮在另一平面的问题。

按键字幕当前在卡片圆角裁切之外绘制，可能超出卡片边界。卡片局部空间因此定义为「卡片矩形 ∪ 按键字幕可能占用的范围」，前景缓冲、投影四角和「适配画布」都按这个范围计算，避免字幕在投影后被裁掉。卡片圆角裁切仍只作用于视频与鼠标层。

建议的数据形状：

```swift
nonisolated struct RecordingCardPose: Codable, Equatable, Sendable {
    var yawDegrees: Double       // 绕 Y 轴：左右倾斜
    var pitchDegrees: Double     // 绕 X 轴：上下倾斜
    var rollDegrees: Double      // 绕 Z 轴：平面旋转
    var scale: Double            // 卡片外层缩放，默认 1
    var translationX: Double     // 相对于画布宽度，默认 0
    var translationY: Double     // 相对于画布高度，默认 0
}

nonisolated struct RecordingMotionCue: Identifiable, Codable, Equatable, Sendable {
    var id: UUID
    var start: TimeInterval      // 源时间，与 ZoomCue 一致
    var end: TimeInterval        // 源时间
    var enterDuration: Double    // 输出秒数，不受片段变速影响
    var exitDuration: Double     // 输出秒数，不受片段变速影响
    var targetPose: RecordingCardPose
    var isEnabled: Bool
    var chainsFromPrevious: Bool // 预留；首版固定为 false
}
```

片段范围以源时间存储，与现有 `ZoomCue` 相同；进入和退出时长以输出秒数表示，所以加速或减速视频片段只改变运镜覆盖的输出范围，不改变倾斜动作本身的速度。这与自动缩放「速度无关」的现有行为一致。

透视镜头角度首版采用固定值，沿用当前截图投影的 24°（`AnnotationBackground` 的默认值），避免同时开放镜头距离和缩放而产生重复控制。初始倾斜范围建议为 ±45°、平面旋转 ±30°。在 24° 视场角下，45° 偏航会让卡片近端边明显放大并越出画布，所以「适配画布」所需缩放和越界提示要在原型阶段一起验证，最终范围以验证结果为准；所有输入必须限制为有限值。

运镜片段的目标姿态采用绝对值。基础姿态变化时，片段仍前往原目标姿态；片段外与片段首尾使用新的基础姿态。检查器明确区分「基础姿态」和「片段目标」。

`RecordingMotionTimeline.frame(at:)` 只依赖已保存状态和给定时间，不依赖播放顺序、上次渲染时间或实时动画状态。任意跳转、倒着拖动、30 / 60 fps 导出都得到一致姿态。

首版采用五次平滑插值 `6u⁵ − 15u⁴ + 10u³`，使进入和退出的端点速度与加速度为零。角度范围受限，因此不需要先引入四元数；弹簧曲线和大角度环绕留到后续。

## 5. 时间线规则

运镜以源时间存储、在编辑后时间线上求值，不使用 SwiftUI 隐式动画驱动。剪辑操作（删除、分割、变速、文本剪辑、去除静音）**不修改运镜片段**，与 `ZoomCue` 相同；剪辑结果完全由求值时经 `RecordingClipTimeline` 的映射得到。这样剪辑撤销天然与运镜一致，不需要额外的撤销分组或碰撞规范化。

求值步骤：

1. 用 `RecordingClipTimeline.editorTime(forSourceTime:)` 求出片段源范围中仍被保留的第一个与最后一个编辑时间，得到片段在输出中的有效范围 `[editorStart, editorEnd]`。完全被删除的片段不参与求值，但仍保留在项目中，撤销删除后即恢复。
2. 进入阶段从 `editorStart` 开始，退出阶段在 `editorEnd` 结束，均按输出秒数计算。
3. 有效范围不足 `enterDuration + exitDuration` 时，按比例缩短进入和退出阶段，保持时间最小为零。
4. 有效范围内部的剪切点不打断运镜：姿态沿编辑后时间连续求值，与自动缩放「剪切不打断缩放」的行为一致。

| 操作 | 结果（由映射自动得到） |
| --- | --- |
| 分割视频片段 | 无变化 |
| 删除运镜之外的视频 | 后续运镜随剪辑映射移动 |
| 删除运镜的开头或结尾 | 有效范围缩短，进入 / 退出在新边界处完整重建 |
| 删除运镜中间 | 有效范围跨越剪切点，运镜连续，不产生姿态跳变 |
| 修改片段速度 | 覆盖的输出范围随之伸缩；进入 / 退出秒数不变 |
| 运镜所在视频被全部删除 | 运镜不显示；撤销后恢复 |
| 撤销剪辑操作 | 运镜随映射恢复，无需单独处理 |

由于剪辑映射保持顺序（片段不能重排），源时间中互不重叠的运镜在输出中也不会重叠，编辑运镜时只需在源时间上约束相邻边界。

检查器在片段被剪辑缩短时显示实际生效的进入 / 退出时长，避免用户看到的数值和观感不一致。自由关键帧版本再考虑「保留局部曲线」的方式。

## 6. 统一投影与预览

新增 `RecordingCardProjection`，输入卡片局部矩形、画布尺寸和姿态，输出目标四角、正向 / 逆向单应矩阵以及投影范围。

- 预览、导出与编辑命中测试共用四角计算和矩阵。
- 模型坐标保持归一化；像素换算只发生在布局与渲染边界。
- 统一使用左上角坐标，Core Image 的 Y 轴翻转集中在适配层。
- 固定旋转顺序和旋转中心，并将投影算法版本写入项目，避免以后修改数学模型导致旧项目外观变化。
- 从截图几何中提取纯数学公共部分时，保留历史 `projectionVersion` 路径，并验证截图输出未变化。视频模型不直接持有截图设置类型。
- 数学与时间线类型显式 `nonisolated` / `Sendable`；SwiftUI 状态仍留在 MainActor。

预览不依赖 SwiftUI 的 `projectionEffect`：播放器是 `NSViewRepresentable` 承载的 `AVPlayerLayer`，SwiftUI 的投影修饰符作用在 AppKit 宿主视图上很可能不生效或只应用仿射部分。首选方案：

- 在 `StudioPlayerContainerView` 中建立卡片 layer 树：视频、鼠标与点击效果、按键字幕都作为同一容器 layer 的子 layer，容器应用由共享矩阵生成的 `CATransform3D`（含 `m34` 透视项）。Core Animation 原生支持透视，`AVPlayerLayer` 在 3D 变换下工作良好。
- 鼠标、点击效果和按键字幕从 SwiftUI overlay 迁入这棵 layer 树，避免把同一矩阵分别交给 SwiftUI 和 CALayer 时出现不同步。未启用运镜时可继续使用现有 SwiftUI overlay。
- 更新 layer 变换时关闭隐式动画，由 `RecordingMotionTimeline.frame(at:)` 逐帧驱动。

预览的层次顺序按第 4 节合成流程重排：当前 `.shadow` 加在卡片投影之前，若直接在外层套用投影，阴影会被一起投影，与导出的画布空间阴影不一致。启用运镜时，阴影由投影后的卡片外形在画布空间生成。

若 layer 透视在圆角遮罩、透明边缘或性能上不能满足要求，再切换为 `AVPlayerItemVideoOutput` 获取预览纹理，由 Metal 预览视图绘制。该替代路径在原型阶段决定，不先重写现有播放器。

投影越界时，保持固定画布和用户参数，明确提示可能被裁切。「适配画布」显式计算覆盖整个动作的固定缩放，并保存结果；播放期间不偷偷改变缩放。接近投影奇点或无效四角时，采用确定性的安全姿态回退并报告错误，不使用“上一次有效帧”作为依赖播放顺序的回退状态。

## 7. 导出实现

### 首版：正确性优先的 Core Image 路径

现有 Core Graphics 导出路径只能将画面绘制到矩形，不能直接表达需要的透视关系。对启用运镜的项目增加卡片前景缓冲：

1. 在可复用的透明 BGRA 缓冲中绘制卡片内容，包括鼠标、点击效果和按键字幕；缓冲按第 4 节定义的卡片局部空间分配，包含按键字幕的溢出范围。
2. 按目标四角通过 `CIPerspectiveTransform` 投影前景。
3. 从投影后的 alpha 生成阴影，在画布空间应用模糊和偏移。
4. 合成背景、卡片、摄像头与转写字幕，写入编码器的输出缓冲。

复用 `CIContext`、像素缓冲池、遮罩和纹理，避免逐帧创建。背景可继续缓存；运镜开启时卡片阴影不能保留在静态 backdrop 中。

未启用运镜或姿态完全为默认值的项目沿用当前导出路径，以保留现有性能和画面行为。固定倾斜也进入新的投影路径。

### 运动模糊与缓存

把原来的矩形采样扩展为 `RecordingRenderSample`，同一个子帧时间同时取得内容 viewport、卡片 pose 和相关 overlay 状态。

- 使用当前一帧长度的快门间隔。
- 根据投影四角的最大位移选择子帧数，不能只根据未投影矩形位移判断运动。
- 对透明前景及 alpha 使用预乘颜色进行加权累积，再与背景合成，避免透明边缘发黑。
- 子帧沿用当前屏幕视频帧，先实现运镜导致的模糊；不扩大为解码多个源视频帧的完整视频光流效果。
- 硬剪切两侧分开采样，快门不跨剪切混合两段不同内容。
- 摄像头与转写字幕按输出帧正常合成，保持清晰。
- 缓存键加入姿态、投影、圆角和必要前景状态；鼠标、按键等在变化时不得错误复用包含它们的完整卡片缓存。
- 保存、分享和无窗口导出都传递相同时间线，运镜修改必须让已缓存的最终视频失效。

首版不承诺与静态平面导出相同的速度。先测量 Core Image 路径，若达不到验收预算，再进入 Metal 优化阶段。

### 后续：Metal 合并与加速

现有 Metal renderer 的输入是多个 `CGRect`，需要扩展为投影矩阵、内容采样区域和遮罩参数。每个输出像素通过逆单应矩阵映射到卡片局部坐标，再映射到源视频 UV。

鼠标与按键先做成卡片局部 overlay 纹理，和视频使用同一投影。动态阴影独立合成。优化后仍保留 Core Image 作为参考和失败回退路径。

## 8. 项目格式与兼容

- 在当前编辑文档格式 5 基础上增加下一格式版本。
- 保存基础姿态、总开关、运镜片段（源时间范围）和投影算法版本。
- 缺失字段默认关闭运镜、姿态为 identity、片段为空，使旧项目行为保持原样。
- 静态基础姿态可纳入样式预设；带时间的片段留在具体项目中，不随普通样式预设导出。
- 旧版应用无法呈现新效果，不宣称降级编辑后能无损保留新字段。
- 工程存储、原始轨道和现有可编辑文件继续使用当前路径。

## 9. 实施顺序与 PR 划分

开发分支沿用仓库现有的描述性命名（如 `video-3d-motion-prototype`），PR 只提交到 `helson-lin/Screendrop`。

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| A：渲染原型 | 固定姿态、卡片 layer 树透视预览、短视频导出样本；不发布半成品功能 | layer 透视预览可用，鼠标与按键字幕跟随透视，Core Image 导出与投影位置一致；identity 姿态强制走新路径时，输出与旧路径像素一致（或在颜色容差内）；24° 视场角下的倾斜范围与「适配画布」完成验证 |
| B：固定倾斜 | 正式检查器、项目保存、撤销、导出及分享 | 旧项目无变化，新项目重开一致，裁剪 / 缩放模式不冲突 |
| C：时间线运镜 | 运镜轨道、预设、进出阶段；剪辑联动由源时间映射得到 | 任意跳转确定性；删除开头 / 结尾 / 中间、变速、全部删除后撤销均符合第 5 节表格 |
| D：质量与优化 | 动态阴影、透视运动模糊、缓存及性能优化 | 30 / 60 fps、横竖比例、透明边缘和导出取消均通过 |

每个可交付阶段分别做原子提交和 PR。渲染原型属于实验验证，默认不暴露给用户；可发布版本必须覆盖预览、项目存储和导出整条链路。

## 10. 验证与验收

项目没有测试 target，使用独立数学检查脚本、渲染对照样本与 Xcode 构建验证；不为每个滑块增加镜像实现的测试。

重点检查：

1. identity 与未启用状态保持原效果；旧截图投影路径无回归。
2. 四角对应关系、逆映射和坐标轴方向正确；极端输入不会产生 NaN 或崩溃。
3. 在同一输出尺寸和时间点比对预览几何与导出四角，几何误差目标不超过 1 个输出像素；颜色与抗锯齿单独设容差。
4. 检查片段开始、保持、结束，以及硬剪切前后一帧；保存重开、任意跳转、撤销重做均一致。
5. 检查鼠标、点击效果、按键字幕随卡片投影，转写字幕和摄像头保持画布布局。
6. 检查圆角、透明边缘、阴影、无背景、运动模糊和素材边缘裁切。
7. 检查 1080p / 4K，30 / 60 fps，16:9 / 9:16 / 1:1，Fill / Fit 与手动裁剪。
8. 检查前景缓存失效、最终导出缓存失效、取消导出和关闭编辑器后的资源释放。
9. 性能目标：1080p 预览帧预算争取 16.7 ms；在相同机器和样本上记录导出时间与峰值内存，验证重复渲染不会持续增长。4K 预览可使用有界降采样，完整导出保留目标分辨率。

原型阶段优先验证四个风险：`AVPlayerLayer` 在 layer 透视下的圆角与透明边缘是否可靠、卡片 overlay 迁入 layer 树后与导出是否一致、大角度倾斜下的画布越界与适配缩放、透视运动模糊的内存与时间成本。
